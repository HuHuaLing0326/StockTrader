> 用途：让另一个能读取本地文件的大模型为一个参考仓库建立一份**轻量索引**：每个功能在哪些文件里、对应哪些测试和文档。索引只回答"在哪里"，不回答"怎么实现"。具体细节由《参考项目源码专题整理任务书》按功能逐个深挖。

# 提示词正文

## 待填参数

| 参数 | 取值 |
|---|---|
| 项目代号 | 【wm 或 ww】 |
| 仓库路径 | 【wm：D:\documents\MyCodes\stock-wm；ww：D:\documents\MyCodes\WeiWei-stock】 |
| 输出文件 | 【D:\documents\MyCodes\StockTrader\docs\reference\索引-项目代号.md】 |

## 一、任务

为上面的仓库建立一份索引，写入输出文件。读者是另一个负责开发新系统的大模型。它会根据索引快速找到某个功能的代码，再去深入阅读。

索引要做到：给定一个功能（例如"交易日历"或"印花税计算"），读者能在几分钟内找到相关的文件、函数、测试和文档。

**这不是一次详细整理。** 不要摘录接口参数、字段位置、规则取值、实现细节，这些留给专题整理。索引控制在 600 行以内。

## 二、规则

1. 只读仓库：不修改仓库文件，不运行代码和测试，不安装依赖，不联网。可以列目录、搜索文本、统计行数、读取文件。
2. 不抄录密钥、token、cookie、邮箱、webhook 地址；环境变量只记名称。
3. 路径一律相对仓库根目录，关键函数写"路径:行号"或"路径 + 函数名"。
4. 只写仓库里有的东西；不确定的标【未确认】；某个功能域找不到对应代码，写"未发现"并注明搜索过的关键词。
5. 判断文件用途时，读文件开头、类和函数签名、文档字符串即可，不要通读实现。

## 三、索引内容

### 3.1 项目概况

1. 一句话定位：根据代码说明这个项目实际在做什么。
2. 两层目录结构：每个目录一句话说明用途，并给出代码行数。
3. 入口：命令行入口、主脚本、后台服务、界面，以及各自的启动方式。
4. 运行形态与平台依赖：常驻进程、定时任务、子进程；Windows 服务、systemd、fcntl 等平台相关代码的位置。
5. 关键依赖与版本，以锁文件为准。
6. 配置：配置定义在哪里、如何加载；环境变量名称和用途。

### 3.2 功能域地图（索引的主体）

每个功能域一行：

| 功能域 | 主要文件 | 关键类/函数 | 对应测试文件 | 相关文档 | 代码行数（约） | 备注 |
|---|---|---|---|---|---|---|

功能域至少覆盖以下各项，没有的写"未发现"；仓库里有、但不在下面列表中的功能，追加在表末：

- 数据：证券标识与板块判定、传输层与防封禁、交易日历、日线与复权、全市场快照、实时报价、财务数据、资金流、筹码与资本事件、一致预期与研报、宏观、公告、新闻与网页正文、存储与迁移、缓存、健康台账与同步审计；
- 分析：大盘状态、候选初筛、因子与技术特征、研究证据包、策略打分与预测；
- 智能体：角色与编排、提示词、结构化输出、模型路由与后备、上下文管理、记忆、技能与 SOP；
- 交易：组合计划、订单闸门、盘中信号、模拟券商、费用与交易规则、持仓批次与分红、成交审计、风控与守卫、交易权限与适当性；

- 运行：调度与定时任务、持久化工作流、运行控制、监控告警、报告、通知、部署、备份、运维命令行。
