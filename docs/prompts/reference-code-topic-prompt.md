# 参考项目源码专题整理任务书

> 用途：让另一个能读取本地文件的大模型，针对**一个功能专题**深入阅读参考仓库，产出一份具体、可核对的专题资料。每次只做一个专题，范围限定在与该专题相关的代码。
>
> 使用方法：
> 1. 在第五节"专题清单"里选一个专题，把它的编号、名称和默认问题填进"待填参数"。问题可以增删。
> 2. 如果已经用《参考项目源码索引任务书》生成了索引，填上索引路径，大模型会从索引定位文件；没有索引也可以，大模型会自己搜索。
> 3. 把"提示词正文"及之后的内容发给大模型。
> 4. 建议跟着开发进度走：开发到哪一步，就做哪一步对应的专题，不要提前全部做完。
>
> 版本：1.1　日期：2026-10-25

# 提示词正文

| wm 仓库路径 | D:\documents\MyCodes\stock-wm |

| 输出文件 | 【D:\documents\MyCodes\StockTrader\docs\reference\topics\专题编号-专题名称.md】 |
| 本次要回答的问题 | 【从第五节复制该专题的默认问题，可增删】 |

## 一、任务

我正在开发一个新的 A 股研究与模拟交易系统（StockTrader，技术栈为 Python、AgentScope 2.0、ReMe、DuckDB），会借鉴两个参考项目：

- **wm**：基于 TradingAgents-CN 的大模型多智能体分析与模拟交易系统，规模大、功能全；
- **ww**：以确定性因子、回测和纸面交易为主的量化研究系统，结构较简单。

请只针对上面指定的**一个专题**阅读参考仓库，回答"本次要回答的问题"，并按第四节的结构写入输出文件。读者是负责开发新系统的大模型，它会根据你给出的"文件:行号"回到源码核对，所以内容必须具体、准确、可核对。

你的任务不包括：为新系统做设计、重构参考仓库、给出投资建议。

## 二、范围控制

1. 从索引中该专题对应的功能域开始。没有索引时，用专题相关的关键词搜索定位。
2. 只读与本专题直接相关的文件和函数；沿调用关系最多向外追一层。
3. 读到与本专题相关、但属于其他专题的内容，只在"范围外线索"一节记下位置，不要展开阅读。
4. 如果发现本专题涉及的文件超过 15 个，先列出文件清单，说明哪些是核心、哪些是外围，只深读核心文件，并在覆盖说明里写明。

## 三、规则

### 3.1 只读与安全

1. 不修改、不新建、不删除仓库内的文件；产出只写入输出文件。
2. 不运行项目代码、测试或脚本，不安装依赖，不发出网络请求。可以使用只读命令。
3. 不抄录密钥、token、密码、cookie、账号、邮箱、webhook 地址，遇到时写"【已脱敏】"并注明位置。公开数据源的服务器地址可以照录。

### 3.2 证据与标注

1. 每条信息注明位置，格式为"相对仓库根目录的路径:起始行-结束行"；两个仓库都读时，路径前加仓库代号，如 `wm:src/ashare_agent/data/calendar.py:120-158`。
2. 每条信息带一个证据标签：

   | 标签 | 含义 |
   |---|---|
   | 【代码】 | 在代码中直接读到的实现 |
   | 【测试】 | 来自测试用例的断言或测试数据 |
   | 【配置】 | 来自配置文件或配置类的默认值 |
   | 【文档】 | 仓库文档中写明，但没有在代码里核实 |
   | 【注释】 | 来自代码注释 |
   | 【推断】 | 根据代码做出的推断 |
   | 【未确认】 | 找到线索但无法确定 |

3. 只写仓库里有的东西，不要用你对 akshare、东方财富、A 股规则等的一般知识去补充或纠正。你认为仓库写错了，标【推断】并说明理由。
4. 问题找不到答案时，写"**未发现**"，并写明搜索过的关键词和范围。

### 3.3 忠实摘录

1. 接口地址、参数名、请求头、字段名、字段位置、常量、阈值、费率、单位换算系数，一律原样照录。
2. 动态拼接的地址或参数，写出拼接规则和涉及的变量。
3. 代码片段只在必要时引用，每段不超过 20 行。字段位置表、常量表可以完整摘录。
4. 实验结果、统计数字原样照录，并注明出处。

## 四、输出结构

两个仓库都读时，第 1 到 7 节按仓库分别写（先 wm 后 ww），第 8 节做对比。只读一个仓库时，跳过第 8 节。某一节与本专题无关时，写"不适用"。

1. **问题解答**：逐条回答"本次要回答的问题"，每条附位置和证据标签。
2. **实现位置与调用链**：核心文件、类和函数；一到两条关键调用链，按"函数 → 函数"写出，每步附位置。
3. **外部接口细节**（专题涉及外部数据源时必填）：每个接口一个小节，逐项写明：
   - 调用方式：直接 HTTP 的方法、地址模板、全部参数、请求头（Referer、User-Agent、Cookie 是否必需）；或第三方库的库名、版本、函数名、参数；或 TCP 服务器地址和选择方式；
   - 响应格式与编码、解码方式；
   - 解析方式：按位置解析的，完整摘录字段位置表；按列名解析的，列出所用字段；
   - 每个数值字段的原始单位和换算规则；
   - 股票、指数、ETF 的区分方式；复权参数；
   - 时间语义：是否区分盘中与收盘后、是否为累计序列、可见时间如何确定；
   - 分页、行数上限、时间窗口限制；
   - 限流、风控、断路器参数和已知封禁现象；
   - 失败识别与分类；缓存规则；
   - 在回退链中的位置，切换后如何标注来源。
4. **规则、常量与默认参数**：

   | 名称 | 取值（原样照录） | 适用范围 | 位置 | 证据标签 |
   |---|---|---|---|---|

5. **数据结构**：相关的数据库表、缓存文件、核心对象，列出字段、类型、单位、键和含义。
6. **坑点与防御**：来自测试、注释、文档和防御分支。

   | 现象或风险 | 根因（如有记载） | 代码中的处理 | 证据 | 位置 | 对应测试 |
   |---|---|---|---|---|---|

7. **设计理由与不一致**：
   - 文档、注释中明确记载的设计理由；没有记载就写"理由未记载"；
   - 文档与代码不一致之处、空实现、默认关闭的功能、TODO 记载的已知缺陷。
8. **两仓库对比**（两个仓库都读时）：

   | 方面 | wm 的做法 | ww 的做法 | 差异说明 |
   |---|---|---|---|

9. **借鉴评述**：本节允许写你的判断，全部视为【推断】。列出值得借鉴的做法、不建议借鉴的做法，以及新系统开发者最容易忽略的细节。
10. **范围外线索**：读到但未展开的相关内容，附位置和所属专题。
11. **覆盖说明**：读过的文件、跳过的文件及原因、仍不确定的地方、没有回答的问题。

## 五、专题清单

按新系统的开发顺序排列。默认问题可以增删。

### 第 1 步：数据层

**T01 证券标识与板块判定**
- 代码如何规范化输入（前缀、后缀、大小写）？
- 交易所、板块、品种类型的判定规则表是什么？依据写在哪里？
- 同一个 6 位代码既是股票又是指数时，如何区分？
- ST 和风险警示如何识别、何时刷新？

**T02 传输层与防封禁**
- 统一请求入口在哪里？有没有绕过它的请求路径，包括第三方库发出的请求？
- 节流、随机抖动、跨线程串行化如何实现？默认参数是多少？
- 重试和不重试的错误如何分类？断路器的阈值、冷却期、状态持久化方式是什么？
- 代理和编码检测如何处理？

**T03 交易日历**
- 用了哪些数据源，优先级如何？如何检查返回范围是否完整覆盖请求范围？
- 无法核实时返回什么？调用方如何处理？
- 缓存规则是什么？查询下一个交易日时的窗口如何设置？
- 交易时段常量和时区如何处理？

**T04 日线与复权**
- 股票、指数、ETF 分别走哪些数据源？优先级和理由？
- 各数据源的字段、单位、复权参数是什么？复权因子从哪里来？
- 缓存的定型规则是什么？前复权数据如何避免跨时间拼接？
- 停牌日如何处理？有没有多源交叉校验？

**T05 全市场快照与实时报价**
- 用了哪些接口？字段位置表和单位换算是什么？
- 停牌、无有效报价如何识别？涨跌停价从哪里来？
- 实时性和缓存规则是什么？主数据源失败时如何切换？

**T06 存储、同步审计与健康台账**
- 用了什么数据库？单写入者和并发写入如何实现？
- 写入如何保证幂等？表结构和迁移如何管理？
- 同步审计和覆盖率如何计算、判定完成状态？
- 健康台账记录哪些字段？如何查询？

### 第 2 步：模拟交易与对照组

**T07 模拟券商与账本**
- 订单从生成到成交的生命周期和状态是什么？成交价格和时点如何确定？
- T+1、整手、涨跌停、滑点如何实现？
- 佣金、过户费、印花税的费率和计算方式？ETF 如何处理？
- 持仓批次、分红和红利税如何记账？成交后审计检查哪些项？多账户如何隔离？

**T08 对照组账户与每日估值**
- 有哪些对照组？各自的行为规则是什么？如何与主策略隔离？
- 每日估值在价格缺失时如何处理？

### 第 3 步：大盘状态、初筛与因子

**T09 大盘状态与候选初筛**
- 大盘状态的输入、公式、分档阈值是什么？如何影响仓位？
- 初筛的步骤、过滤条件、名额分配是什么？快照拿不到时如何处理？

**T10 因子与回测引擎**
- 有哪些因子？计算口径、窗口、价格口径、缺失处理分别是什么？
- 如何保证因子只用当日及之前的数据？有哪些因果性测试？
- 回测的成交假设、成本和约束是什么？标签和样本切分如何设计？

### 第 4、5 步：证据与多智能体分析

**T11 研究证据包（结构化数据部分）**
- 证据包包含哪些类别？每类数据的来源、陈旧期和可见时间规则是什么？
- 数据缺口如何表示？证据如何按角色分发？

**T12 多智能体分析与结构化输出**
- 有哪些角色？职责、工具、上下文来源、输出结构分别是什么？提示词在哪里？
- 执行顺序和交接格式是什么？会话如何持久化？
- 概率输出的格式和校验方式？模型不可用时如何处理？
- 辩论消融、实体匿名化等实验的设置和结果数字是什么？

**T13 确定性守卫与风控**
- 有哪些守卫可以否决或改写大模型的输出？触发条件分别是什么？
- 仓位上限、资金纪律、交易权限如何实现？作用范围如何声明？

### 第 6 步：从计划到订单

**T14 组合计划与订单闸门**
- 组合计划检查哪些一致性？仓位如何封顶？
- 订单闸门在下单前重新读取哪些状态？演练模式如何实现？

### 第 7 步：评估

**T15 评估与统计**
- 前瞻收益如何跟踪？概率评分用了哪些指标和公式？
- 用了哪些小样本统计方法？公式和参数是什么？
- 回放和一致性检验如何做？有哪些实验结论，包括负结果？

### 第 8 步：自动运行

**T16 调度与无人值守运行**
- 有哪些定时任务？触发时间、交易日条件、依赖、锁、超时、重试和补跑规则是什么？
- 进程模型、断点恢复、运行控制（暂停、恢复）如何实现？
- 部署方式和平台相关代码在哪里？

**T17 报告与通知**
- 有哪些报告？内容结构和生成时点是什么？
- 通知渠道、去重和限流如何实现？推送失败如何处理？

### 第 9 步：记忆

**T18 记忆与学习**
- 记忆如何抽取、分类、写入、过期？
- 召回时如何按时间过滤，如何防止事后才知道的信息进入决策？
- 学习反馈和校准笔记如何生成、如何使用？

### 第 10 步：扩展

**T19 文本证据链**
- 新闻搜索、正文抓取、PDF 解析如何实现？URL 安全校验如何做？
- 外部文本如何清洗和防提示注入？
- 论断抽取、引文核验、复核的流程和阈值是什么？来源可信度如何评分？

**T20 盘中信号与事件触发**
- 信号收件箱的结构、有效期、过期处理是什么？
- 盘中决策在什么时段、什么条件下消费信号？
- 事件触发的条件和生成的任务是什么？

## 六、交付前自检与最终回复

交付前逐项检查：

1. 每条信息都有位置和证据标签；
2. 没有抄录任何密钥和个人信息；
3. 随机抽 5 条，回到源码核对位置和内容，并记录核对结果；
4. 地址、参数、字段位置、常量是原样照录；
5. 没有答案的问题写明了"未发现"和搜索范围。

最终用中文回复：

1. 输出文件路径；
2. 本专题最重要的 5 条发现，附位置；
3. 没有回答的问题及原因；
4. 范围外线索的数量和所属专题；
5. 自检结果，包括抽查核对的记录。
